# LazyVim Migration Design

**Date:** 2026-06-08
**Scope:** Migrate `nvim/` from a customized kickstart.nvim base to a [LazyVim](https://www.lazyvim.org/installation) distribution.

## Goal

**Less maintenance.** Stop hand-maintaining LSP/cmp/treesitter/formatter/picker wiring. Let LazyVim own the defaults and Extras; carry over only the customizations LazyVim does not cover.

## Guiding principle

Maximal LazyVim adoption. This is a **rewrite of `nvim/` into LazyVim's structure**, not a file-by-file port. For every concern, prefer the LazyVim default or an official Extra. Only write custom specs/keymaps for behavior LazyVim genuinely lacks.

## Requirements (what must survive the migration)

These are expressed as capabilities/bindings, not specific plugins:

- `<leader><leader>` → fuzzy find files (picker-agnostic; will use fzf-lua).
- `<leader>ff` → browse/navigate file structure rooted at the current buffer's directory (picker-style, **not** a tree — a file-tree explorer is explicitly not wanted).
- `<leader>s.` → live grep in the current buffer's directory.
- `<leader>m` local-leader tree: format + test workflow + alternate-file (see below).
- `<leader>wo` → maximize current window.
- File-path yank keymaps (`<leader>fy`, `<leader>fY`).
- Elixir via the **dexter** LSP (not elixirls/nextls).
- The `vim-test` workflow with `neovim_sticky` strategy.
- **Neogit** as the git UI (magit muscle memory from Doom Emacs).
- **dracula** colorscheme.
- The "auto-create parent dirs on save" autocmd.

## Target structure

Replaces the current `nvim/init.lua` + `nvim/lua/plugins/*` + `nvim/lua/custom/*`.

```
nvim/
├── init.lua                      # require("config.lazy")
├── lua/
│   ├── config/
│   │   ├── lazy.lua              # bootstrap lazy.nvim, import LazyVim + extras + plugins
│   │   ├── options.lua           # kept vim.o options
│   │   ├── keymaps.lua           # ONLY keymaps LazyVim doesn't cover
│   │   └── autocmds.lua          # AutoCreateParentDirs autocmd + Brewfile filetype
│   └── plugins/
│       ├── colorscheme.lua       # dracula, set as LazyVim colorscheme
│       ├── git.lua               # Neogit (+ diffview), overrides <leader>gg
│       ├── elixir.lua            # dexter LSP override on top of elixir Extra
│       ├── editor.lua            # fzf-lua keymap overrides (<leader><leader>, <leader>ff, <leader>s.)
│       ├── test.lua              # vim-test + <leader>mt* maps
│       ├── lsp.lua               # non-Extra servers: fish_lsp, sqlls
│       └── misc.lua              # other.nvim, maximize.nvim
├── .stylua.toml                  # unchanged
└── lazyvim.json                  # generated by LazyVim: tracks enabled extras
```

## Backup / rollback strategy

This replaces a working config, so backups are layered:

1. **Git branch.** All migration work happens on a feature branch (`lazyvim-migration`); `main` retains the working kickstart config. This is the primary rollback.
2. **Committed `nvim-backup/` directory.** Before the migration branch, copy the current `nvim/` → `nvim-backup/` and commit it on `main`. It is a stow package that is **never symlinked** — it exists only as a ready-to-restore reference that survives the eventual merge.
3. **Runtime state reset (manual, documented).** LazyVim and kickstart cannot share Neovim runtime state. Before first LazyVim launch, rename aside:
   - `~/.local/share/nvim` → `~/.local/share/nvim.bak`
   - `~/.local/state/nvim` → `~/.local/state/nvim.bak`
   - `~/.cache/nvim` → `~/.cache/nvim.bak`

   Reversible by renaming back. This is documented in the spec/README, not automated in `setup.sh`.

## What gets DROPPED

Deleted because LazyVim covers them as good-or-better defaults:

| Dropped | Replaced by (LazyVim) |
|---|---|
| `telescope.lua` (+ fzf-native, ui-select, file-browser) | fzf-lua (default picker) |
| `lsp.lua` (mason wiring, flat server list, handlers) | LazyVim nvim-lspconfig + mason + lang Extras |
| `blink-cmp.lua` | LazyVim ships blink.cmp |
| `conform.lua` | LazyVim ships conform; stylua / mix format via Extras |
| `lint.lua` | LazyVim ships nvim-lint; markdownlint via markdown Extra |
| `mini.lua` (ai/comment/pairs/surround/statusline) | mini.ai, mini.pairs, mini.surround, lualine, built-in comments |
| `which-key.lua` config + window/tab/buffer trees | LazyVim which-key + default `<leader>w/b/g/<tab>` maps |
| `gitsigns.lua` custom maps | LazyVim gitsigns + `<leader>gh*` maps |
| `indent_line.lua` | LazyVim indent-blankline + snacks indent |
| `autopairs.lua` | mini.pairs |
| `guess-indent`, `todo-comments`, `nvim-notify`, `hardtime.nvim` | guess-indent→snacks; todo-comments shipped; notify→snacks.notifier; hardtime dropped entirely |
| `custom/plugins/delete_file.lua` | unused; dropped |
| Window/tab/buffer keymaps, `<Esc>` nohlsearch, file save/save-as/rename/delete keymaps | LazyVim defaults (`<C-s>`, snacks.rename, `<leader>bd`, etc.) |
| dracula Neogit diff-highlight autocmd | dropped (fragile; Neogit + diffview highlight natively) |

## Extras to enable (`lua/config/lazy.lua`)

- `lazyvim.plugins.extras.lang.elixir` — treesitter + `mix format` (LSP overridden, see Elixir section).
- `lazyvim.plugins.extras.lang.rust`
- `lazyvim.plugins.extras.lang.typescript`
- `lazyvim.plugins.extras.lang.json`
- `lazyvim.plugins.extras.lang.yaml`
- `lazyvim.plugins.extras.lang.docker`
- `lazyvim.plugins.extras.lang.markdown`

Lua support (lazydev + stylua) is in LazyVim core — no Extra.

**Manual LSP servers** not covered by an Extra (`lua/plugins/lsp.lua`): `fish_lsp`, `sqlls`. (`html`, `cssls`, `bashls`, `ruff`, `marksman` arrive via the Extras above or core.)

## Keymaps carried over

Audited against LazyVim defaults; only the genuinely-missing are kept.

**`lua/config/keymaps.lua`:**
- `<leader>fy` → yank absolute file path to clipboard.
- `<leader>fY` → yank project-relative file path to clipboard.

**`lua/plugins/editor.lua` (fzf-lua overrides):**
- `<leader><leader>` → fzf-lua `git_files` (fall back to `files`).
- `<leader>ff` → fzf-lua `files` rooted at the current buffer's directory.
- `<leader>s.` → fzf-lua `live_grep` in the current buffer's directory.

**`lua/plugins/test.lua` + `misc.lua` (the `<leader>m` tree):**
- `<leader>mf` → format buffer (conform).
- `<leader>mtt` / `<leader>mtT` → alternate file (other.nvim), normal / vsplit.
- `<leader>mtv` → `:w | TestFile`
- `<leader>mts` → `:w | TestNearest`
- `<leader>mta` → `:TestSuite`
- `<leader>mtr` → `:TestLast`
- which-key groups registered: `<leader>m` (+local leader), `<leader>mt` (+tests).
- `<leader>wo` → maximize.nvim toggle.

**Dropped keymaps** (LazyVim covers): `<leader>fD` delete, `<leader>fs` save, `<leader>fS` save-as, `<leader>fR` rename, all `<leader>w/t/b` window/tab/buffer trees, `<Esc>` nohlsearch.

## Git: Neogit (`lua/plugins/git.lua`)

- `NeogitOrg/neogit` with deps `nvim-lua/plenary.nvim`, `sindrets/diffview.nvim`. **Drop** the telescope dependency (fzf-lua is the picker; Neogit uses `vim.ui.select` / snacks).
- Carry over custom popup remaps: `F` → `PullPopup`, `p` → `PushPopup`, `P` → `false`.
- `<leader>gg` → `neogit.open { kind = 'replace' }`. This **overrides** LazyVim's default `<leader>gg` → lazygit; LazyVim's lazygit keymap is remapped/disabled to avoid conflict.
- lazygit remains installed (already in Brewfile) but is no longer the primary git UI.

## Elixir / dexter (`lua/plugins/elixir.lua`)

- Elixir Extra provides treesitter + `mix format`.
- Override the LSP: disable `elixirls`/`nextls` from the Extra; register `dexter` as today using LazyVim's `vim.lsp.config` / nvim-lspconfig pattern:
  - `cmd = { 'dexter', 'lsp' }`
  - `filetypes = { 'elixir', 'eelixir', 'heex' }`
  - root markers: `.dexter/dexter.db`, `.dexter.db`, `mix.exs`, `.git`
- dexter is installed via mise/brew (not Mason) — unchanged.

## Kept options & autocmds

LazyVim sets most options itself. Carry over only non-defaults:

**`lua/config/options.lua`:** `scrolloff = 10`, `confirm = true`, `listchars` (`tab`/`trail`/`nbsp`). Verify `relativenumber` (LazyVim default on) and leader (`<space>`, already default) need no action. Set `vim.g.have_nerd_font = true` (a nerd font — `font-hack-nerd-font` — is in the Brewfile).

**`lua/config/autocmds.lua`:** AutoCreateParentDirs (mkdir parents on `BufWritePre`); `Brewfile` → `ruby` filetype mapping.

## Brewfile / setup.sh / docs

- **Brewfile:** no changes. `fzf`, `fd`, `ripgrep`, `git-delta`, `lazygit`, and `font-hack-nerd-font` are all already present.
- **setup.sh:** nvim stow target (`$HOME/.config/nvim`) unchanged. The runtime-state reset is documented, not scripted.
- **CLAUDE.md:** update the "Neovim Architecture" section — new `config/`+`plugins/` structure, LazyVim/Extras model, Neogit `<leader>gg`, fzf-lua keys, dexter override location.

## Out of scope

- No changes to other stow packages.
- No neotest (vim-test kept).
- No file-tree explorer.
- hardtime.nvim and nvim-notify are not carried over.

## Open tradeoffs (accepted)

- Picker keys for everything except the three overridden bindings will be LazyVim/fzf-lua defaults — intentional relearning as part of maximal adoption.
- dracula Neogit diff highlights are not recreated.
